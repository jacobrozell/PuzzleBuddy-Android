## 2. New work from the iOS delta (D1–D9)

Each item names the iOS source at tag `1.1.0` and the WP it belongs in.

### D1. Stats: count finish logs on every puzzle → ✅ done 2026-11-05

**iOS:** `App/Helpers/CollectionStats.swift` (`completionCount(in: puzzles…)`, `completionsByMonth(in: puzzles…)`). Review fix #44.

**Bug on Android today:** `domain/catalog/CollectionStats.kt:150-169` builds `completionsThisMonth`, `completionsThisYear`, and `completionsByMonthThisYear` from `completed`. After **Puzzle again**, the old finish sits on an In Progress puzzle. The chart counts it and the month card does not.

**Fix:** pass every puzzle, not `completed`, to those three. Leave `completedCount` and the other metrics on `completed`.

**Test:** port `testReplayLogCountsWhilePuzzleIsInProgress`: an In Progress puzzle with one finish this month gives `completedCount == 0`, month == 1, year == 1, and the bucket for this month == 1.

### D2. `PuzzleCompletion.ratingLabel` → ✅ done 2026-11-05

**iOS:** `App/Helpers/PuzzleCompletion.swift`.

Add `val ratingLabel: String?` to `domain/completion/PuzzleCompletion.kt`. It is null when the rating is null or ≤ 0. Round to tenths. A whole number gives `"Rated 4"`. A half gives `"Rated 4.5"`.

**Test:** port `testRatingLabelOmitsUnratedAndKeepsHalves`. Also assert `ratingLabel` is null in the existing time-label test.

### D3. Completion history section → do with WP5.1

**iOS:** `App/Views/PuzzleViews/PuzzleCompletionHistorySection.swift`, `PuzzleDetail.swift`.

- Show the section when `completions.isNotEmpty() || status == COMPLETED`. With no logs, show "No completion logs yet".
- Row summary is date · time · rating, joined with `" · "`. The content description adds `", {time}"` and `", {rating}"` in that order.
- Each row has two targets. Tapping the row body opens the edit sheet. A trash `IconButton` (48 dp, warm accent text color) asks for confirmation and then removes the log. Content description: "Remove completion {n}". Do **not** rely on swipe only. Long-press can still offer Edit and Remove.
- The header can wrap to two lines.

### D4. Undo-completion banner layout → do with WP5.2

**iOS:** `PuzzleDetail.swift` (`undoCompletionBanner`).

At large font scale (`LocalDensity.current.fontScale >= 1.3`, the same threshold the list row already uses for stacking), put the message on top and Undo and ✕ on a row underneath. Otherwise use one row: message, Undo, ✕. Undo stays on one line and shrinks to fit. Both buttons are at least 48 dp.

### D5. Overdue "Due back" value → ✅ done 2026-11-05 (detail screen)

**iOS:** `PuzzleDetail.swift` (`detailRow(valueColor:)`).

When `PuzzleLoanSemantics.isOverdue`, draw the "Due back" value in the warm accent text color. Long detail values wrap to 4 lines.

### D6. Timer card accessibility → do with WP5.3

**iOS:** `App/Views/PuzzleViews/PuzzleTimerCard.swift`.

The elapsed readout is now spoken. Give it `contentDescription = PuzzleTimerSemantics.spokenLabel(elapsed)` and `liveRegion = LiveRegionMode.Polite`. Throttle it to once a minute so TalkBack does not read every tick. The start/pause button's `stateDescription` is now only "running" or "paused". Reset stays on one line.

### D7. Contrast tokens and list polish → ✅ done 2026-11-05

**iOS:** `App/Util/DesignTokens.swift`, `PuzzleStatusPill.swift`, `PuzzleList.swift`, `PuzzleCell.swift`, `PuzzleForm.swift`.

- Add `accentText` and `accentWarmText` to `ui/theme/Theme.kt`. Today it only has `accentWarm`. Copy the light and dark values from iOS `DesignTokens.swift`. Use them wherever **text or icons** sit on a surface: the Completed and Wishlist status pills, the active filter button, Clear filters, the form's total-time preview, Use timer time, and the secondary button style (border at 45% alpha). Fills and backgrounds stay on `accent`.
- List header: the result count can wrap to two lines. The filter controls move to **their own row** below the count, not to the right of it.
- Filter chips shrink text a little before they truncate.
- Row badges: the On loan / Overdue badge can wrap to two lines. Badges use `FlowRow` so they drop to a new line when they do not fit, and they stay stacked at large font scale.
- Empty-state accessibility: merge the text into one node when there is no Add button. Keep the children separate when there is one.

### D8. iPhone Duo chrome → out of scope, with one check

The Duo mechanics (`DuoFloatingAddBar`, sidebar, `LandscapeTabClearance`) are iOS only, as the 10-28 plan says. Two ideas carry over cheaply. Do them in WP4.1 if they fit:

- Overflow and toolbar actions have a text label as well as an icon: "Pick my next puzzle", "Check duplicate", "More", "Add puzzle".
- Form and sheet Done is a confirm action with a check icon.

**Check in M5:** run the existing `AdaptiveTwoPane` on a foldable emulator (Pixel Fold or 7.6" Fold-in) in both postures. Fix only what breaks.

iOS 1.1.0 is on `main` now. In `.github/workflows/ci.yml:28`, change `ref: feature/1.2.0-puzzle-timer` to `ref: 1.1.0`. ## 6. M2 results (2026-11-05)

WP4.1–4.4 and WP4.8–4.11 are in, plus D5, D7, and the D8 action labels. 239 unit tests pass. Checked on the Medium Phone API 36.1 emulator in light, dark, and at 150% font: demo load, list filters and counts, add, edit, discard prompt, detail live update, Puzzle again, Settings, onboarding copy, and the reset banner.

**Bugs found and fixed on the way:**
- Text fields in the form lost focus as soon as the keyboard opened. `ReadableContentWidth` picked its landscape branch from the box height, so the keyboard shrinking the height rebuilt the content.
- Brand, store, and notes were trimmed on every keystroke, so a space between words was dropped.
- The detail screen loaded once and showed stale data after an edit.
- Swipe, detail Delete, and Settings Delete All ran without asking, or with the old "puzzles only" copy.
- A failed save (such as a duplicate barcode) crashed the form coroutine.
- The scanner re-bound the camera on every recomposition.
- The onboarding overlay left the app underneath in the TalkBack tree.
- White text on the brand teal is 4.0:1. In-progress pills and the Cover badge use a darker teal (7.6:1). iOS has the same pairing; worth a look there.

**Deliberate differences from iOS:**
- Quick add reuses the full form with the iOS quick-add sections on top, instead of a separate short sheet.
- At large font sizes the six status tabs become a status menu, like the iOS split-view picker.
- Replay onboarding stays in Settings > About. iOS 1.1 does not have it.

**Not checked on a device:** gallery and camera photo picking, barcode scanning with a camera, the tablet layout, and a TalkBack pass. These belong to M5.

**Carried into M3:**
- Pick next and Share entries in the list toolbar (WP4.5, WP4.7).
- `StoreReviewPrompt.recordSettingsLinkOpened()` on Write a Review, and the review prompt after a scan or edit (WP5.6).
- Marking What's New as seen when onboarding finishes (WP5.5).
